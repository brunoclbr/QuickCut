# Local editing companion

## Purpose and ownership
Codex or your AI app of choice handles conversation, setup and video editing. This app is a read-only companion. It shows what has happened and where things are: the drop folder for new videos, project folders, original footage locations, numbered drafts, Markdown documents and recorded approvals. It streams existing media unchanged and builds copyable instructions for the AI app. It never writes files, creates folders, records approvals, uploads, renders, runs AI or executes commands. Three owner-approved exceptions (the third is Approve, below): the ElevenLabs API key (the Setup page can connect, change or remove it so the key never passes through the AI app; handled by `system/voiceover/service.mjs`, stored in the macOS Keychain) and Show in Finder (opens a Finder window on a file inside `workspace/`; changes nothing). It has no database or deployment configuration.

The `createApp({root})` interface contains the workspace/file logic behind the local HTTP interface, and accepts a root folder for isolated testing. Browser UI code owns presentation only. Existing video-scoped helpers/compositions still own editing and rendering.

## Start / open
Node 22+; no additional app dependencies (the optional ElevenLabs connection uses the SDK installed in `system/voiceover/`). macOS only for now.
From the repo root run `node system/app/launch.mjs`. The launcher is finite: it reuses a healthy server for this folder or detaches a new server, verifies health and opens the actual URL with macOS `open`. `--no-open` skips browser launch. Preferred port is set in `config.json` (currently 3005 to leave another project's port 3000 alone). `PORT=3020 node system/app/launch.mjs` overrides that starting port. An occupied port is skipped, not reclaimed.

For foreground debugging only: `node system/app/server.mjs` (stop with Ctrl-C). Ordinary user handoff should use the persistent launcher. Runtime URL/PID is in `.runtime.json`, logs in `.runtime.log`; these are local ignored files. To stop the detached server, inspect that runtime record and verify the PID still belongs to this app before sending SIGTERM. A missing/stale record is not permission to stop arbitrary Node processes.

## App interface
Only `GET` and `HEAD` are accepted, plus two credential endpoints and Show in Finder; every other method returns 405.
- `POST /api/approve` `{project, draft, version}` (owner-approved 2026-10-28): same-origin JSON only. Appends the approval record to the video's `feedback.md`, copies the draft (`drafts/<file>`, a video) to `finished-videos/<name>[-vertical|-square|-youtube].mp4` (temp copy then rename; the copy happens before the record, so a failure leaves no approval) and makes `poster.jpg` (best effort, ffmpeg). Refuses a versionless finished file when versions exist and the reverse (409). Never renders or deletes.
- `POST /api/reveal` `{path}`: Show in Finder (`open -R`, macOS). Same-origin JSON only (same checks as the key endpoints); the path must be inside `workspace/` and pass the traversal/symlink checks. Opens a window; writes nothing.
- `POST /api/voiceover/connect` `{apiKey}` and `POST /api/voiceover/disconnect`: require an `Origin` matching this server, `Sec-Fetch-Site: same-origin` when sent, `Content-Type: application/json` and a body ≤ 4 KB. Connect validates the key with free ElevenLabs lookups before saving it to the Keychain. Responses are the connection status only; the key is never returned, logged or written to a file.
- `GET /api/health`: app identity and canonical root; used by launcher.
- `GET /api/state`: projects folder status (`workspace`: the name from `workspace/preferences/workspace.md`; each project also reports `approvedOn`, the date in its last approval record, `poster` and its disk use `bytes`), asset-library summary (from `system/assets/library.mjs` status), drop folder (`workspace/drop-videos-here/`) contents, whether it exists and its "moved to" notes, finished videos (`workspace/finished-videos/`), projects with drafts, `source/` files and whether `source/` exists, recorded approval, assets, an asset overview (sounds and music listed, fonts, icon/animation/illustration counts), when the repo last changed (read from `.git/logs/HEAD`, no git command; null outside git), document paths and the ElevenLabs status (connected, account, checks, preferred voice; never the key). Reads the filesystem on each request.
- `GET /api/tools`: bounded detection of Node/FFmpeg/Whisper, not setup certification. It never installs tools.
- `GET /api/document?path=...`: plain Markdown; no raw HTML execution.
- `GET /inter.ttf`: the repo's licensed Inter font (OFL) for the UI; system fonts are the fallback. `GET /brand-mono.ttf`, `/brand-mono-bold.ttf`, `/brand-sans.ttf`, `/brand-mincho.ttf`: the brand's IBM Plex Mono, IBM Plex Sans and Shippori Mincho (OFL) from `workspace/assets/fonts/` for the Brand page.
- `GET/HEAD /media?path=...`: allowed workspace image/audio/video formats; range requests for seeking; no transcoding.

An approval is shown when a project's `feedback.md` contains a block starting with `## Approved version` followed by `Draft: drafts/<file>` for a draft that exists (the AI app writes this; see root `AGENTS.md`). The first video's legacy `Filename: … accepted as final` line is also recognized.

Server binds only to 127.0.0.1; no CORS, strict Host/Origin checks and CSP. Rejects traversal, hidden paths and symlink escapes. Factor choices and prompt fields exist only in the browser; copy them into the AI app.

Browser support depends on source codecs; Safari/QuickTime may be needed for HEVC/HDR. The app streams unchanged files rather than converting color silently. Only files inside `workspace/` are served; footage stored elsewhere (as for the first video) is listed in that project's brief.

## Interface
Sidebar with four pages (headed by the workspace's name, read from `workspace/preferences/workspace.md`; an unnamed workspace shows a "Name this workspace" card): **Videos** (default: a summary strip (videos, waiting for review, finished, raw, last activity, disk use), a banner when new footage waits in the drop folder, then one row per video, found by its name, as a sortable **table** (default) or **cards** (remembered in the browser), with a search box and filters with counts. A video is "Waiting for your review" (drafts, no approval), "Finished" or "Raw footage". Posters come from `workspace/projects/<name>/poster.jpg` when present. The cards show the status, the approved draft and its date, each finished version (Final, Vertical, Square or YouTube 16:9) with Show in Finder, and buttons to open the video or show its drafts in Finder. Finished files are matched to a video by name: `<name>.mp4`, `<name>-vertical.mp4`, `<name>-square.mp4`, `<name>-youtube.mp4`. Below, folded away: "Where things are in Finder" and things to say to the AI app), **Video** (one video: its final versions first, a player, drafts newest first with plain titles and a ✓ on the approved one, real metadata, a reminder when the newest draft is not approved, copyable approval and feedback, a tip with a template for polishing long notes in ChatGPT first, and "Feedback & context": how the AI app re-reads all of feedback.md, the notes split by draft, and a copyable "earlier notes are settled" instruction), **Brand** (palette, type, caption and card samples and the reference video, all read from the editing guide at runtime; nothing stored) and **Setup & preferences** (a "This workspace" card with the name, the one-brand-per-copy reminder, a copyable "make a clean copy" instruction and a getting-started checklist; status, the "Make it yours" note, a "Keep QuickCut up to date" panel with a copyable git pull instruction, the ElevenLabs panel, preferences, environment, assets by topic with download links, and the factor explorer). Markdown is rendered by a small DOM-only renderer in `app.js` (no raw HTML); each document can also be viewed raw. Design tokens live at the top of `styles.css`.

## Development
- `npm --prefix system/app test`: isolated Node tests, temporary fixture workspaces; no actual video pipeline or user documents changed.
- `node --check system/app/server.mjs` and `node --check system/app/public/app.js`: syntax checks.
- `npm --prefix system/app run smoke`: optional real-Chrome UI checks using temporary fixtures. Requires installed Chrome on macOS (or `CHROME` pointing to a compatible browser).
- UI: `public/index.html`, `public/styles.css`, `public/app.js`; no build step.
- Server: `server.mjs`; launcher: `launch.mjs`.

No third-party example catalog or remote preview dependencies. Illustrative factor diagrams are original CSS/UI, not video renders or generated imagery added to footage. Clean ZIP packaging and other operating systems are not part of this MVP.
